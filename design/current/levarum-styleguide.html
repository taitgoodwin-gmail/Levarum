LEVARUM DESIGN SYSTEM — V1.0

The style guide is the source of truth.

Five approved base colours, two typefaces, one 4px spacing unit. Every other value on this page is derived from those and the derivation is stated next to it. Nothing here is decorative.

How to read the badges. Every number is a computed WCAG contrast ratio, not an estimate. Outlined = AA at all sizes (≥4.5:1). Rust = large text only (≥3:1, meaning ≥24px, or ≥19px bold). Filled = fails at every size; usage restriction stated.

Typefaces are declared as Poppins and Lora with system fallbacks. This page makes no external requests, so the specimens render in the fallback faces unless those families are installed locally — see NOT VERIFIED at the end.

PART A · 01

Naming convention

One convention, applied without exception: --{category}-{role}-{variant}. Roles describe the job, never the appearance — --color-surface-raised, never --color-beige-2. Categories in use: color, font, line-height, letter-spacing, space, radius, border-width, shadow, duration, ease, container, breakpoint, focus-ring, touch-target. One token, one name, one place.

PART A · 07

Motion and breakpoints

  • --duration-fast 180ms, --ease-out — a control changing state (button, chip, field border). Reduced motion: 0ms, colour changes instantly.
  • --duration-base 280ms, --ease-out — disclosure: accordion open, step change. Reduced motion: 0ms, content appears with no transform.
  • --duration-slow 620ms, --ease-out — entrance choreography and the logo lift. Reduced motion: removed entirely, not shortened — elements start at their final position and opacity.
  • --breakpoint-min 320px — the narrowest supported width. Nothing may clip or scroll horizontally here.
  • --breakpoint-nav 680px — below this the nav stacks: mark and wordmark on their own line, links beneath, left aligned.
  • --breakpoint-wide 900px — below this all two-column layouts become one column, in source order.
  • --container-page 1180px max, --gutter 24px each side.
PART B

Components

Only components that exist on the ten Levarum pages. States that the current build does not have are named as GAPs, not designed silently.

Primary button

Tokens: --color-accent fill, --color-on-accent label, --radius-md, --font-heading 600 at 19px. Minimum target 44px (built at 58px). Keyboard: focusable, Enter and Space activate, focus ring is --color-focus-ring at 2px with 3px offset. At 320px it goes full width and the label stays on one line.

The 19px 600 label is what makes --color-on-accent legal on rust: 4.14:1 clears the 3:1 large-text threshold. A 17px regular label on rust would be a defect.

GAP — loading state. The build has no submitting or in-flight state for any primary button. Blocks: the intake unlock step, where a slow send currently looks like a dead tap.

Secondary button

Tokens: transparent fill, --border-width-strong in --color-text-primary, label --color-text-primary at 17px 600. Same target and keyboard behaviour as primary.

GAP — disabled secondary. Not designed. Blocks nothing today; the only secondary is Back, which is never disabled.

Text link

Tokens: --color-text-accent (6.69:1), underline on hover, colour to --color-text-primary on hover. Focus ring as above. Inline links inherit body size; nav links use --font-size-xs in --color-text-secondary.

PART C

Patterns

  • Container. 1180px max with a 24px gutter. Nothing sits edge to edge except full-width colour bands, which keep the same inner container.
  • Prose width. Body copy is capped at 62ch. Lead paragraphs cap at 560px. A line of body text never exceeds either.
  • Form column. 520px max, one field per row, label above field, 12px between label and field, 20px between fields.
  • Marketing page template. Nav, hero (headline + lead + one action), one dark band, card row, closing action, footer. One dark band per page, never two.
  • Intake step template. Nav, progress plus step text, H1, lead, one card holding the question, action row with primary right and Back left. One decision per screen.
  • Result template. Eyebrow, figure, lead, summary of what was answered, named rows, fix-first block, one action, quiet restart link.
  • Responsive behaviour, stated as behaviour. Two columns become one in source order below 900px. The nav stacks below 680px. Type scales fluidly between the 2xl and 3xl steps rather than jumping. Touch targets never fall below 44px at any width. At 320px nothing clips and nothing scrolls sideways.

CLOSING

Gaps, assertions, and what was not verified

GAPS

  • Semantic success, warning, info — no honest derivation from a two-hue palette; left undefined. Blocks confirmation and status UI.
  • Loading / in-flight state — no primary button or screen has one. Blocks the unlock step on a slow connection.
  • Disabled secondary button — undesigned; nothing needs it today.
  • Number input — the only one was the rate field, removed with money; no states specified.
  • Empty, failure and expired-link states on the plan — undesigned.
  • Stone has no text role at any size (2.57:1). If a design ever needs a third text tone, that tone does not exist yet and must be derived and re-tested.
  • Radius migration — the built pages use 22px and 16px card radii; the scale says 20px and 13px. The pages are the thing that is wrong, but migration is out of scope here.

Banned-value assertion

Both artifacts were checked, case-insensitively, against all seven values on the banned list — Anthropic's brand palette. The values are deliberately not reproduced here: printing them would put them inside the very output the assertion is about. Result: zero occurrences in levarum-tokens.css and zero in this page, at any opacity, including inside rgba() values. Re-run the check against your own copy of the list.

NOT VERIFIED

  • Typeface rendering. Poppins and Lora are declared but not embedded, because the page must make no external requests. If those families are not installed locally, every specimen above renders in the fallback and the optical sizes of the scale are unconfirmed.
  • 320px behaviour. Stated as rules for every component; not rendered at 320px and not measured.
  • Hover, active and focus states. Rendered as static specimens with the state's tokens applied, not triggered by a real pointer or keyboard.
  • Reduced-motion behaviour. Specified per duration token; not exercised.
  • Every contrast ratio on this page and every derived hex was computed, not estimated — those are verified.

One visual defect noticed while working, noted and moved past: the built pages' card radii and the Schibsted Grotesk / Instrument Sans pairing predate this system and disagree with it. Migration is a separate job and needs the defect audit first.
