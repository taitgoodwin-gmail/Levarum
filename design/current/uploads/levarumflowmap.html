The hypothesis this map suggests

You said your workflow "doesn't seem to start at the home page — it starts at the intake." This map offers a reason: Start is the only page with a defined job, and it has no exit. The other four inform; only Start converts, and the moment a visitor submits, the site stops existing. Nothing tells them what happens next.

If that is right, the fix is not a new home page. It is giving the four upper pages an exit that points at Start, and giving Start an exit that points at you. Confidence: moderate. It rests on the project summary, not on reading the files.

What this map needs to become real

  1. The eight project files, so every Gap above resolves to an actual answer instead of a guess.
  2. Your call-availability window — the confirmation page cannot be written without it.
  3. The intake field list, which determines the Airtable schema.
  4. A decision on whether the editor tweak controls ship to production. My read: strip all of them.
